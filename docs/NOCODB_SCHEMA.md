# NocoDB Schema Specification

This document is the exact table/column spec the backend code expects. NocoDB itself
is **not** deployed by this repo — stand up your own instance (Docker, self-hosted, or
NocoDB Cloud), create these 4 tables, then point `.env` at it:

```
NOCODB_BASE_URL=https://nocodb.your-domain.com
NOCODB_API_TOKEN=...
NOCODB_BASE_ID=...
```

Each table below must expose its **Table ID** (not just its display name) — the
backend's `NOCODB_TABLE_*` env vars should be set to those NocoDB table IDs
(found in NocoDB under Table → API Snippet, or Swagger docs for your base).

---

## 1. Managers

| Column | Type | Constraint | Notes |
|---|---|---|---|
| `Manager_ID` | Single Line Text (255) | **Primary Key** | Authenticated Google email (`user_email`). Tenant anchor — never changes. |
| `Manager_Name` | Single Line Text (255) | Not Null | Display name from Google profile. |

## 2. Chittis

| Column | Type | Constraint | Notes |
|---|---|---|---|
| `Chitti_ID` | Single Line Text (100) | **Primary Key** | e.g. `C01A2B3C4D` — generated by backend on onboarding. |
| `Manager_ID` | Single Line Text (255) | **Foreign Key** → Managers | Every query is scoped by this. |
| `Chitti_Name` | Single Line Text (255) | Not Null | |
| `Rule_Template` | Single Line Text (100) | Not Null | e.g. `Incremental Model V1` |
| `Total_Members` | Number | Check `> 0` | S |
| `Total_Months` | Number | Check `> 0` | M |
| `Monthly_Commission` | Decimal | Not Null | C |
| `Undrawn_Due` | Decimal | Not Null | D_undrawn |
| `Drawn_Due` | Decimal | Not Null | D_drawn |
| `Cycle_Anchor_Day` | Single Select | Enum: `1st,5th,10th,15th,20th,25th` | Fixed billing anchor — no free text. |
| `Current_Active_Month` | Number | Default `1` | Tracks active cycle. |
| `Start_Month_Year` | Single Line Text (20) | Optional | e.g. `2026-10`, drives n8n cron matching. |

## 3. Shares

| Column | Type | Constraint | Notes |
|---|---|---|---|
| `Share_ID` | Single Line Text (100) | **Primary Key** | Custom, manager-assigned (e.g. `CHAND1`). |
| `Chitti_ID` | Single Line Text (100) | **Foreign Key** → Chittis | |
| `Manager_ID` | Single Line Text (255) | **Foreign Key** → Managers | Composite-indexed with Chitti_ID recommended. |
| `Member_Name` | Single Line Text (255) | Not Null | |
| `Phone_Number` | Single Line Text (20) | Not Null | `+91XXXXXXXXXX` format. |
| `Draw_Status` | Single Select | Enum: `Undrawn,Drawn` | |
| `Month_Drawn` | Number | Nullable | Set only when Draw_Status = Drawn. |
| `Advance_Credit` | Decimal | Default `0.00` | Ledger balance from overpayments. |

**Recommended index:** composite on (`Manager_ID`, `Chitti_ID`) for fast roster queries.

## 4. Transactions

| Column | Type | Constraint | Notes |
|---|---|---|---|
| `Trans_ID` | Single Line Text (100) | **Primary Key** | Composite: `{Chitti_ID}_M{Month}_{Share_ID}` — enforce as a **unique index** to guarantee spawn idempotency. |
| `Share_ID` | Single Line Text (100) | **Foreign Key** → Shares, Indexed | |
| `Month_Number` | Number | Indexed | |
| `Amount_Due` | Decimal | Not Null | |
| `Amount_Paid` | Decimal | Default `0.00` | |
| `Pending_Dues` | Decimal | Computed or app-managed | `Amount_Due - Amount_Paid`, floored at 0. The backend writes this value explicitly rather than relying on a NocoDB formula field, for portability. |
| `Payment_Status` | Single Select | Enum: `Pending,Partial,Verified` | |
| `Payment_Date` | DateTime | System-set | Backend writes `datetime.now(UTC)` on every payment — no date pickers anywhere in the UI. |

**Critical:** Do **not** pre-populate future Transaction rows. Rows are created
only by `POST /api/chittis/{chitti_id}/spawn-month`, exactly S rows per call
(one per active share), per the On-Demand Cycle Spawning model.

## Optional 5th table (not required by current code, but recommended)

## 5. Receipts (extends the Google Drive Vault integration)

| Column | Type | Constraint | Notes |
|---|---|---|---|
| `Receipt_ID` | Single Line Text | **Primary Key** | Auto-generated. |
| `Share_ID` | Single Line Text | **Foreign Key** → Shares | |
| `Upload_Date` | DateTime | System-set | |
| `Drive_View_URL` | URL | Not Null | Google Drive `webViewLink`. |
| `Drive_File_ID` | Single Line Text | Not Null | For future deletion/management. |

The `drive.py` router currently returns this metadata in its response without
persisting it — wire up a `create_record` call against this table if you want
the "100-Receipt Rolling Gallery" to be queryable.

## API Token & Base setup checklist

1. In NocoDB, create a Base (project) for ClearFlow.
2. Create the 4 (or 5) tables above with exact column names — the backend
   code references these fields by name (e.g. `chitti["Total_Members"]`).
3. Generate an API Token: **Account Settings → Tokens → Create New Token**.
4. Copy each table's **Table ID** into the corresponding `NOCODB_TABLE_*`
   variable in `.env` (NOT the display name — NocoDB's v2 API addresses
   tables by ID).
5. Set `NOCODB_BASE_URL` to your instance root (e.g. `https://nocodb.example.com`,
   no trailing `/api/...`).
